# Jesse James Garrett：《The Elements of User Experience》增强深度报告

## 一、源报告映射与证据边界

- 源报告：`01-book-report/0157 - Garrett：《The elements of user experience user-centered design for the Web and beyond》.深度报告.md`
- 版本入口：源语料明确出现第二版题名页和第二版导言。
- 源语料规模：约24.1万字符，包含2,054行，章节结构较完整。
- 元数据说明：源报告仅保留作者姓氏“Garrett”，正文题名页明确出现Jesse James Garrett。
- 文献性质：源报告误识别为“文集／选读”；正文实际是围绕用户体验五层模型组织的系统性方法著作。
- 主要证据：战略层、范围层、结构层、框架层和表现层；产品目标、用户需求、功能规格、内容需求、交互设计、信息架构、导航、信息设计、线框图和视觉设计。

本报告不把五层模型处理成必须顺序执行的瀑布流程。该模型的主要价值，是帮助团队区分不同决策层级及其依赖关系；实际项目中各层需要迭代、回溯和并行验证。

## 二、理论定位：用户体验是多层决策一致性的结果

Garrett反对把用户体验等同于页面外观或可用性测试。用户从产品中感受到的结果，是组织目标、用户需求、功能与内容、交互结构、导航、界面和视觉表达共同作用的结果。

```text
战略层：产品目标＋用户需求
→ 范围层：功能规格＋内容需求
→ 结构层：交互设计＋信息架构
→ 框架层：界面＋导航＋信息设计
→ 表现层：感知形式与视觉语言
```

五层之间具有双向影响：上层决策为下层提供理由，下层原型和测试又可能暴露上层假设错误。模型的核心不是五张平行图，而是“每个形式决定都应能追溯到更高层目标”。

## 三、核心理论解析

### 1. 战略层把组织目标与用户需求并置

源报告明确区分产品目标与狭义商业目标。政府、学校、非营利机构和开源项目同样拥有产品目标。战略层必须回答：组织希望实现什么，用户为何愿意投入时间，两者是否冲突。

```text
组织目标
＋用户需求
＋成功指标
＋伦理与制度边界
＝可讨论的产品战略
```

战略不是项目开端写完后永不改变的文件。源报告指出，战略应成为起点，但不必在所有工作开始前完全固定。新证据出现时，应回到战略层修订。

### 2. 用户需求不是功能愿望清单

用户提出的功能要求往往只是对现状的回应。研究者需要识别背后的任务、动机、能力和约束。

例如，“增加导出按钮”可能源于跨系统协作、数据所有权、离线工作或审批制度。若只增加按钮，可能无法解决真正问题。

用户需求应通过访谈、观察、支持记录、行为数据和利益相关者材料交叉验证，并区分：主要用户、间接用户、受影响但不直接操作的人，以及维护与审核人员。

### 3. 范围层把抽象目标转为可验证要求

范围层包含功能规格与内容需求。源报告强调需求必须可证伪，即能够判断何时未被满足。

模糊要求如“界面应现代”“搜索应智能”无法验证。更有效的要求应说明：谁在何种情境完成什么任务、需要何种信息、成功标准是什么、异常如何处理。

范围管理也是政治过程。功能进入路线图意味着资源获得优先权；未被记录的无障碍、维护、内容更新和退出需求容易在后期消失。

### 4. 结构层区分交互设计与信息架构

交互设计关注系统如何响应用户行为，包括状态、流程、反馈和错误恢复；信息架构关注内容如何分类、命名和组织。

```text
交互设计：用户做什么—系统如何回应
信息架构：内容是什么—彼此如何关联
```

二者并非完全分离。电子商务、知识库和社交平台同时需要行为流程与内容结构。分类会影响可以执行的动作，动作也会改变内容状态。

### 5. 概念模型必须服务用户理解

数字产品常借用购物车、文件夹、电话、书架等现实概念。概念模型可以降低学习成本，但过度隐喻会遮蔽数字系统的真实能力和风险。

研究者应检查：用户是否能够预测系统状态；对象是否保持一致；同一动作是否在不同页面含义不同；后台数据关系是否通过界面产生误导。

### 6. 导航是信息架构的可见入口

源报告指出，信息架构为内容建立结构，导航是用户看见和穿行这一结构的镜头。导航设计至少需要支持：当前位置、可去何处、如何返回、当前路径与整体结构的关系。

导航系统包括全局、局部、上下文、辅助和搜索。任何单一菜单都无法承担全部任务。对于复杂网站，还应处理深层链接、登录前后状态、浏览历史和跨设备连续性。

### 7. 框架层协调界面、导航与信息设计

框架层决定按钮、输入、导航、信息和行动如何占据有限空间。源报告强调，界面不仅收集用户信息，也需要向用户传达信息，因此信息设计是交互设计的一部分。

框架的关键不是把所有功能塞进页面，而是：

- 优先行动是否明显；
- 相关信息是否临近；
- 频繁任务是否高效；
- 危险操作是否有区分；
- 系统状态是否持续可见；
- 不同屏幕尺寸是否保持任务连续性。

### 8. 线框图是跨层协商文件

线框图把信息、功能、导航和优先级放进同一结构，使团队在视觉风格之前讨论系统关系。它不是低保真成品，也不是跳过内容的灰色方框。

有效线框图应标明真实内容类型、动态状态、错误、空状态、权限差异和响应式变化。只有“正常页面”的线框图会掩盖系统复杂性。

### 9. 表现层不是最后装饰

视觉、字体、色彩、图像、声音和动效影响注意力、可读性、信任和品牌语气。表现层受前四层约束，也能暴露结构问题。

源报告批评由高管偏好颜色、工程师偏好控件而决定界面的做法。表现层选择必须回到用户研究、内容语义和产品目标，而不能以权力偏好替代设计理由。

### 10. 五层模型需要迭代而非线性执行

实践中，视觉原型可能揭示内容缺失，导航测试可能暴露分类错误，功能开发可能发现战略不可行。因此更准确的模型是：

```text
建立初始五层假设
→ 制作跨层原型
→ 用用户与技术证据检验
→ 回溯上层决策
→ 收敛并记录取舍
```

## 四、设计史关联

### 1. “用户体验”扩展了设计对象

网站和数字产品把内容、软件行为、视觉传播和商业战略结合。五层模型记录了21世纪初用户体验设计如何把这些分工组织为一个专业领域。

### 2. 从网页制作到产品设计

早期网站常由视觉设计与技术实现主导。该书要求在页面之前明确战略、需求、功能和结构，反映网页设计从单页制作向复杂产品系统的转变。

### 3. 信息架构继承书籍、图书馆和导视传统

分类、索引、层级、导航和元数据并非数字时代首次出现。用户体验史应连接书籍设计、目录学、图书馆科学、信息设计和空间导视。

### 4. 线框图成为职业协作媒介

线框图、规格和原型使设计决策能够在产品经理、设计师、开发者和客户之间传递。它们既是设计工具，也是组织责任的记录。

## 五、可操作的五层研究模型

针对一个数字产品，可按以下方式审计：

1. **战略层**：组织目标、用户需求、伦理边界和成功指标；
2. **范围层**：功能、内容、无障碍、维护和数据要求；
3. **结构层**：任务流程、对象关系、分类和权限；
4. **框架层**：界面、导航、信息呈现和响应状态；
5. **表现层**：字体、颜色、图像、声音、动效与品牌；
6. **跨层追溯**：每项设计能否说明来自何种需求；
7. **异常路径**：错误、空状态、中断、恢复和退出；
8. **部署后证据**：行为数据、投诉、无障碍问题和长期结果。

## 六、批判性评估

### 1. 五层图可能制造稳定秩序幻觉

真实项目充满组织冲突和技术债务。层级模型便于沟通，但不能掩盖预算、工期和权力如何决定需求。

### 2. 用户中心可能被商业目标吸收

“良好体验带来良好商业”有助于争取资源，也可能让用户研究只服务转化率。应加入用户权利、公共价值和负面外部性指标。

### 3. 模型对服务和平台生态覆盖有限

跨渠道服务涉及人员、政策、物流和后台系统；平台还涉及第三方开发者、内容治理和数据市场。五层需扩展到服务运营与制度层。

### 4. 线框图容易遮蔽真实内容和身体差异

假文、理想数据和标准屏幕会造成虚假整洁。应使用边界内容、多语言、缩放、辅助技术和低带宽情境测试。

### 5. 需求可证伪不代表价值正确

一个要求可以被精确测试，却仍可能用于操控、监控或排除。验证前应先审查目标的正当性。

## 七、研究使用与论文写作

适用于：

- 用户体验设计专业如何形成；
- 五层模型的理论结构和实践局限；
- 信息架构、导航和界面之间的关系；
- 线框图作为跨专业知识媒介；
- 商业目标与用户需求的冲突；
- 从网站设计到平台和服务设计的扩展。

可形成论文判断：

> 五层模型的历史意义，不是提供一套永不改变的网页流程，而是要求数字形式具有可追溯的战略和需求依据；其当代发展则必须把伦理、平台治理和长期维护提升为新的上层约束。

## 八、人工智能时代延伸

AI产品的范围和结构具有不确定性：相同输入可能产生不同结果，模型能力会随版本变化，用户也难以预测数据如何被使用。

五层模型可扩展为：

```text
制度与模型层：数据、模型、政策、责任
→ 战略层：用户价值与组织目标
→ 能力范围层：模型能做什么、不能做什么
→ 对话结构层：意图、状态、工具和恢复
→ 界面框架层：来源、置信度、反馈和人工接管
→ 表现层：语言、语气、视觉与拟人化程度
```

AI用户体验不能只追求对话顺畅。必须让用户理解系统边界、修订结果、查看来源、撤销自动行动并申诉错误。
