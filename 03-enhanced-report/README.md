# 深度报告语义增强工程

## 目标

以规范索引中的全部源深度报告为档案与审计基线，通过模型语义分析增加学术定位、理论解析、设计史关联、批判性评估、课程映射和研究使用价值。

书籍、论文和已治理别名的数量以 [`../config/corpus_baseline.json`](../config/corpus_baseline.json) 为唯一机器可读基线。全量记录用于保留追溯；扣除已治理别名后得到需要独立增强和验收的有效目标。实时统计由覆盖审计生成，不在本说明中复制易过期数字。

## 覆盖审计入口

增强工程的覆盖状态、版本治理、七个 Batch 完成率和逐项明细统一维护于：

- `03-enhanced-report/00-增强报告覆盖审计索引.md`
- `03-enhanced-report/00-增强报告覆盖审计明细.csv`
- `03-enhanced-report/00-重复与版本治理登记.md`

上述审计文件由 `tools/audit_enhanced_reports.py` 自动生成或校验，不以关键词检索数量代替目录全量统计。

## 处理原则

- 保留 `01-book-report` 与 `01-paper-report` 原始报告；
- 新增增强版本，不覆盖原始数据；
- 每份增强报告必须明确映射源文件和源报告；
- 同题异版、重复编号和分卷关系先建立主文件—别名映射，不直接删除；
- 已完成归并的别名标记为 `N/A`，不重复计入有效增强目标；
- `DUPLICATE` 只用于尚未裁定主文件的真实冲突；
- 所有增强结果进入覆盖审计和质量复核；
- `STRUCTURE_COMPLETE` 只表示结构与映射通过；
- `SOURCE_VERIFIED` 表示来源、编号、元数据和最低证据锚点要求通过；
- 只有在 `config/enhanced_content_reviews.csv` 中具有具名人工复核记录的 `CONTENT_REVIEWED` 才计为正式完成；
- 关键词、篇幅和标题数量不能单独产生内容完成状态；
- `REVIEW`、`DUPLICATE` 和 `TODO` 不计为正式完成。

## 阶段

- Batch 01：设计史核心理论类
- Batch 02：现代主义／Bauhaus／设计运动
- Batch 03：设计研究方法
- Batch 04：工业设计与产品文化
- Batch 05：平面设计与视觉传播
- Batch 06：UX／HCI／数字设计
- Batch 07：全球设计史、后殖民与可持续设计

七个 Batch 当前均处于进行中；真实完成数、有效目标和完成率以覆盖审计索引为准。
