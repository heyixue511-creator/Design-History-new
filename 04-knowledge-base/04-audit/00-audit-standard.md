# 知识库质量审计标准

## 一、审计目标

知识库审计不仅检查文件是否存在、字段是否齐全，还要检查知识是否能够被来源支持、是否保持作者原意、是否正确处理版本、实体、关系、争议和权利边界。

审计分为机械审计、证据审计、语义审计、关系审计、跨文献审计和发布审计。

## 二、机械审计

### 必查项

- JSON和JSONL可以解析；
- 记录符合`01-schema/core.schema.json`；
- ID格式正确且全库唯一；
- 必填字段存在；
- 枚举值来自受控词表；
- 引用的来源、证据、实体和概念ID存在；
- `record_version`和时间字段格式正确；
- 被废弃记录包含原因或替代记录；
- 仓库路径使用相对路径；
- 不包含密钥、本机私有路径和未脱敏个人信息。

机械审计通过只表示数据结构可用，不表示学术内容正确。

## 三、来源与版本审计

检查：

- 作者、题名、年份、出版者和资料类型是否与具体版本一致；
- 原版、修订版、译本、节录、书评、数字化版和OCR入口是否被区分；
- 题名时段、作者生年、原版年份和数字化年份是否被误作出版年；
- `same_as`、`duplicate_entry_of`和`translates`是否有足够依据；
- 旧编号和规范主编号的映射是否可撤销、可追溯；
- 权利状态是否从`RIGHTS_AND_SOURCES.csv`正确继承。

## 四、证据审计

### L2最低要求

- 每条证据连接至少一个来源；
- 原始文件路径存在；
- 章节、锚点、字符范围或页码至少有一种有效定位；
- 定位能够机械回查；
- 摘录或转述不超出证据范围；
- 证据类型正确；
- OCR和图像缺失风险被标记。

### 发布阻断项

以下情况不得升级到研究级：

- 证据只指向增强报告而未回到原始来源；
- 锚点无法匹配；
- 图像形式判断没有视觉证据；
- 书评被当作完整专著；
- 来源权利状态和公开导出范围冲突。

## 五、知识原子审计

抽查每条命题是否：

- 只有一个主要判断；
- 主体、谓词和对象清楚；
- 作者主张具有明确主张者；
- 时间、地域、媒介和条件得到限定；
- 没有把频次或共现改写为作者立场；
- 没有把价值判断伪装为事实；
- 没有使用无证据的强因果词；
- 可以单独被支持、反驳或修订。

复合命题率过高时，应回到抽取规则修订，而不是只人工修补少量记录。

## 六、实体与概念审计

检查：

- 规范名称和原文名称均被保留；
- 同名人物、同题作品和同名机构完成必要消歧；
- 人物与其观点分开；
- 作品、出版物和具体版本分开；
- movement、style、concept和period没有混用；
- 术语的不同译法、定义来源和历史变化得到保存；
- 无法消歧的对象保持`candidate`，没有强制合并。

## 七、关系审计

关系按风险分层：

### 低风险

- authored_by；
- published_by；
- located_in；
- uses_material；
- edition_of。

可在元数据明确时自动建立，但仍需抽样核查。

### 中风险

- interprets；
- supports；
- critiques；
- associated_with_style；
- belongs_to_movement。

需要上下文核读或明确二手来源。

### 高风险

- influenced；
- caused；
- derived_from；
- institutionalized；
- excluded；
- appropriated；
- decolonized。

必须人工复核，并记录关系成立的时间、媒介、传播路径和证据边界。

关系审计必须检查方向性。A影响B与B影响A不是同一条关系。

## 八、争议与冲突审计

检查：

- 同一问题的不同立场是否被分别记录；
- 争议对象是否包含主张者和证据；
- 知识库综合是否明确区别于各方立场；
- 少数解释是否因自动聚合被删除；
- `contested`是否被误当成普通低置信度；
- 反例和否定性证据是否能够回查。

## 九、跨文献审计

达到`L5`前至少完成：

- 同一概念在两个以上来源中的定义比较；
- 关键事实的来源互证或冲突识别；
- 同题异版和译本差异核查；
- 重要关系的传播路径或中介检查；
- 对欧美中心、地区缺失、性别缺失、媒介偏差和图像缺失的覆盖审查。

多来源数量不能自动提高置信度；多个来源可能相互抄引或共享同一错误。

## 十、成熟度审计门槛

| 等级 | 必须通过 |
|---|---|
| `L0` | ID、来源入口和基础状态存在 |
| `L1` | 元数据、版本、资料类型和权利初审 |
| `L2` | 证据定位与机械回查 |
| `L3` | 知识类型、原子化和主张者审计 |
| `L4` | 实体、概念、术语和关系审计 |
| `L5` | 跨文献互证、冲突和反例审计 |
| `L6` | 领域、证据、关系、版本和权利人工复核全部通过 |

## 十一、抽样策略

每个批次至少执行：

- 100%机械校验；
- 100%证据锚点校验；
- 100%高风险关系人工复核；
- 100%版本归并人工复核；
- 100%公开导出权利复核；
- 不低于20%的知识原子语义抽查；
- 不低于20%的实体消歧抽查；
- 每类知识对象至少抽查10条；
- 自动抽取规则更新后重新抽查历史记录。

若抽样发现系统性错误，应扩大到全量复核。

## 十二、关键指标

| 指标 | 含义 |
|---|---|
| 来源覆盖率 | 已建立来源记录的文献比例 |
| 证据覆盖率 | 有可回查证据的知识记录比例 |
| 锚点匹配率 | 能在原始文件中机械定位的证据比例 |
| 原子化通过率 | 抽查中符合单一命题标准的比例 |
| 实体规范率 | 已完成规范化或明确候选状态的实体比例 |
| 强关系复核率 | 高风险关系完成人工复核的比例 |
| 版本核定率 | 版本、译本和入口关系已核定比例 |
| 冲突显式率 | 已发现冲突中被建模为争议对象的比例 |
| 权利继承率 | 正确继承来源权利和分发状态的比例 |
| 研究级通过率 | 达到L6的记录比例 |

## 十三、审计输出

每轮应生成：

- 结构校验结果；
- 缺失引用和孤立记录；
- 锚点失败清单；
- 复合命题清单；
- 实体冲突和疑似误归并；
- 高风险候选关系；
- 版本和译本异常；
- 争议缺失和冲突覆盖；
- 权利状态冲突；
- 成熟度分布与降级记录。

## 十四、禁止用作质量证明的指标

以下指标不能单独证明知识质量：

- 文件数量；
- 字符数；
- 标题数量；
- 关键词命中；
- 向量相似度；
- 共现次数；
- 自动摘要数量；
- Schema通过数量；
- `COMPLETE`标签数量。

知识库质量最终由证据、语义、关系、版本、争议、权利和人工复核共同决定。
