# 首批试验后的规则与全库转换方案

本文件汇总任务4要求的七类决策产物。当前结论建立在12项试点的机械验证和候选抽取上；未完成人工语义复核的字段不得升级到研究级。

## 一、模式修订记录

1. `relation.evidence_ids`必须至少包含一项，避免无证据关系通过Schema。
2. 增加`analyzes_source`和`enhances_report`，把原始OCR、深度报告、增强报告之间的仓库派生关系与历史关系分开。
3. 增加弱关系`mentions`；它只表示文本显式提及，不可被解释为认同、影响或因果。
4. `extra.pilot_metric_eligible`区分正文知识记录与仓库入口元数据，防止用管理记录填充试点数量。
5. 证据记录同时保存精确文本锚点与`char_start/char_end`；验证器要求字符范围能够逐字复现锚点。
6. 自动生成的命题统一使用`model_inference`、`candidate`和`semantic_checked=false`，最高停留在L3候选层。
7. 权利字段从来源记录向证据、命题、概念、关系和争议记录传播；`UNVERIFIED`语料只能保持`RESTRICTED`。

## 二、知识颗粒度示例

### 合格候选

“作者在该段把wicked problems与tame problems区分开。”主体、动作和对象单一，可由一个段落支持或反驳。

### 需要拆分

“设计方法运动因社会复杂化而失败，并促成参与式设计、反思实践和设计研究学科化。”该句同时包含原因、失败判断和三项后果，至少应拆为四条，并分别寻找历史证据。

### 禁止自动升级

“A与B在同一段出现，所以A影响B。”共现只可生成`mentions`候选，不能生成`influenced`。

### 操作规则与历史命题分离

About Face中的界面建议应记录为作者的方法陈述；只有存在时间、主体和史料时，才能另建历史事实。

## 三、实体与概念消歧规则

- 人物至少用姓名加任一身份、机构或作品字段消歧；单一姓氏不自动合并。
- 抽象著作、具体版本、数字化入口和OCR文件分别建模，ISBN与出版年用于版本核定。
- 机构改名、合并和职能变化使用事件与时间范围表达，不覆盖旧名称。
- `movement`、`style`、`period`和`concept`保持分型；日常语言相似不是同一实体的证据。
- 术语词频候选必须回读语境，去除普通词、OCR残片和书目噪声后方可规范化。
- 无法确定同一性的记录保持`candidate`，不建立`same_as`。

## 四、关系误判清单

| 候选信号 | 容易误判为 | 允许的自动结果 |
|---|---|---|
| 同段共现 | influenced / agrees_with | mentions |
| 时间先后 | caused / derived_from | 无；只保存时间字段 |
| 相似度较高 | supports / same_as | 比较入口，不写回关系 |
| 书目引用 | agrees_with / influenced | citation_reference证据候选 |
| 相同题名 | same_as / edition_of | 版本核验任务 |
| 方法词出现 | applies_method | 方法候选，等待上下文核读 |
| 地名出现 | occurred_at / active_in | place候选，等待主体与语法核读 |
| 负面词汇 | critiques / contradicts | 立场候选，等待命题级证据 |

`influenced`、`caused`、`derived_from`、`institutionalized`、`excluded`、`appropriated`和`decolonized`始终要求人工复核传播路径、方向、时间与证据边界。

## 五、可自动化字段

- 文件路径、SHA-256、字符范围和精确锚点回查；
- 权利状态、分发状态和仓库暴露状态的继承；
- 来源、深度报告和增强报告的结构入口；
- 每来源的数量、三个代表区段和比较组覆盖；
- JSON Schema、枚举、ID唯一性、引用存在性和生成文件漂移；
- 单句／单段模型命题候选；
- 词汇概念候选与弱文本提及关系；
- 六个比较问题的候选证据数据包。
- 每来源6条查询定向证据及精确字符锚点。
- 分层人工复核队列的确定性生成和决定覆盖层的一致性检查。

自动化结果只能证明可追溯和结构一致，不能证明历史解释正确。

人工决定与机器候选分开保存：生成器可以重复运行而不覆盖审阅结论；最终门根据`queue_id`核验签署者、时间、说明、命题类型、主张者或规范名称。

## 六、必须人工复核的字段

- 命题是否真正原子化，以及证据是否支持完整命题；
- 作者主张、历史事实、编辑解释和模型推断的类型；
- 人物、机构、作品、版本和概念的规范化与同一性；
- 中高风险关系的语义、方向、时间和适用范围；
- 争议双方、反例、竞争解释和少数立场是否被完整保留；
- OCR错误、图像缺失对论证的影响；
- 跨文献比较结论和概念迁移路径；
- 任何公开导出所需的版权或许可依据。

## 七、573项目标的批次、成本与质量方案

### 批次

按每批24—30项安排约20—24批。每批依次执行来源冻结、候选生成、证据回查、20%命题抽样、20%实体抽样、100%高风险关系复核、比较查询和权利检查。发现系统性误差时停止下一批并回滚抽取规则。

### 规模基线

若沿用试点最低线，573项将产生至少17,190条正文证据、11,460条命题、约7,449个候选概念／实体、5,730条关系和573项争议或未解决问题。该规模只用于容量与人员规划，不是完成度证明。

### 人工时间模型

每项建议预留3—5小时：元数据和版本0.25—0.5小时，证据与命题1.5—2.5小时，实体和关系1—1.5小时，争议与比较0.25—0.5小时。全库约需1,719—2,865人工小时，另计版权核验、稀有语言和严重OCR修复。实际成本按“总人工小时×本地复核单价”计算，不在仓库内假定统一货币价格。

### 质量闸门

- 100% Schema与锚点机械校验；
- 每项至少3个代表区段、30条证据和20条命题；
- 不低于20%的命题原子性与支持关系人工抽查；
- 不低于20%的实体候选人工消歧；
- 100%高风险关系、版本合并和公开权利状态人工复核；
- 六类比较查询在每批结束时复跑；
- 任一抽样发现系统性错误时扩大到全量复核，并降低相关记录成熟度。

在首批候选通过上述人工闸门以前，不把当前规则直接扩展到573项，也不将任何受限OCR全文或长摘录公开分发。
